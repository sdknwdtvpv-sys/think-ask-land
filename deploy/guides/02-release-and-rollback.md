# 02 · 发版上线与回滚

> **一句话**：把改好的东西推到线上（https://hanzi.elliotli.work），或者线上出问题时退回上一个版本。
>
> **耗时**：3~6 分钟。**不需要任何密钥。**
>
> **做完你会看到**：屏幕最后出现 `🎉 服务器部署验收全部通过`。

---

## 什么时候用它

- 我改完了代码/内容，想让你亲眼在手机上看到 → 用「发布」
- 线上表现不对（打不开、字词错了、声音不对）→ 用「回滚」

> 平时不用你手动发版：我会在改完后自己跑发布并验证。
> 这份指南是给你"想自己动手"或"我这边不方便时"用的。

---

## 一、发布（把当前代码推到线上）

打开「终端」，粘贴：

```bash
cd "/Volumes/Elliot's SSD/HARNESS/hanzi-kids"
./deploy/release.sh "用一句话说明这次改了什么"
```

引号里那句话会写进版本记录，随便写，例如：`"修好了朗读声音"`。

**屏幕上会依次出现 5 步**，正常长这样：

```
▶ [1/5] 提交到本地仓库
  ✓ 已提交: xxxxx 你的说明
▶ [2/5] 推送到 GitHub
  ✓ 已推送，远端与本地一致
▶ [3/5] 检查预置朗读音频
  ⚠️ ...（音频有缺口时会警告，不影响发布）
▶ [4/5] 部署到腾讯云
  ✅ 已更新: 21M
▶ [5/5] 验证
  ✓ 抽检 9 个关键文件，线上与本地逐字节一致
  ✓ 网站目录无 .git（版本库未泄露）
  🎉 服务器部署验收全部通过
```

**看到最后那句 `🎉 ... 全部通过` 就是成功。**

---

## 二、在手机上确认

1. 打开 https://hanzi.elliotli.work
2. **如果之前把它加到过主屏幕**：直接点图标可能看到旧版（手机缓存）。
   最稳的办法：**删掉主屏幕图标，重新"添加到主屏幕"**。
3. 看一遍你要确认的那个地方（比如点几个字听声音）。

---

## 三、回滚（线上出问题时）

**一条命令退回上一个版本**：

```bash
cd "/Volumes/Elliot's SSD/HARNESS/hanzi-kids"
git revert HEAD --no-edit
./deploy/release.sh --deploy-only
```

`--deploy-only` 表示"不新建提交，直接把当前代码部署上去"，所以它会把你刚 revert 的结果推上线。

**想退回更早的版本**：

```bash
git log --oneline -10          # 看最近 10 次发布，复制你要回去的那条的版本号(前 7 位)
git revert <版本号> --no-edit  # 或 git reset --hard <版本号>（更彻底，但会丢掉之后的提交）
./deploy/release.sh --deploy-only
```

> 拿不准就**别自己回滚**，把 `git log --oneline -10` 的输出发我，我告诉你回哪一条。

## 出错了怎么办

| 现象 | 意思 | 怎么办 |
|---|---|---|
| 最后是 `💥 失败 N 项` | 线上有一个检查没过 | **把失败的那几行发我**（会写清是哪一项） |
| `❌ 线上与本地不一致: xxx` | 文件没传成功 | 再跑一次同样的发布命令；仍失败就发我 |
| `❌ 网站目录出现 .git` | 有泄露风险 | **立刻发我**，这条必须马上处理 |
| `Permission denied` / `ssh` 报错 | 密钥或网络问题 | 发我截图 |
| 发布成功但手机上看还是旧版 | 手机/浏览器缓存 | 删掉主屏幕图标重新添加；或换一个浏览器打开 |
| `command not found: rsync` / `ssh` | 系统缺工具 | 发我截图 |

## 小提示

- **发布前最好先确认测试全绿**：跟我说一声「跑一遍测试」，我会跑完 29 个套件再发。
- **发布是可逆的**：每次发布都是一个独立提交，随时能退回去，不用担心"改坏了收不回来"。
- 这份指南在项目里的位置：`deploy/guides/02-release-and-rollback.md`
