# v2.x 迭代经验与常见坑（v2.1.0 → v2.10.0）

> 这份文档不是"功能介绍"，而是**下次改代码时会救你的那几条**。
> 十个版本一共踩了 10 类坑，其中 6 类是"代码没错、但没人提醒"造成的。
> 每条都写清：症状 → 根因 → 现在由哪个测试守着。

---

## 一、发布动作（每个版本都必须做，缺一不可）

```bash
# 1. 改 index.html 的 app-version
# 2. 打版本戳（同时重生成 sw.js 预缓存清单）
node .build/stamp-assets.js

# 3. 全量回归（必须全绿才往下走）
bash .build/run-all.sh

# 4. 发布（提交 → 推 GitHub → 部署腾讯云 → 真实浏览器线上验收）
./deploy/release.sh "vX.Y.Z 一句话说明" --full-verify

# 5. 打 tag 并推送
git tag -a vX.Y.Z -m "..." && git push origin vX.Y.Z
```

**顺序不能换**：先打版本戳再跑回归。资源 URL 带 `?v=`，`sw.js` 的预缓存清单也带 ——
忘了打戳会造成"线上 HTML 是新的、JS 还是旧的"这种最难查的不一致。

**`--full-verify` 不要省**：v2.9.0 那个"整词听写静默崩掉"的 bug，
jsdom 的冒烟测试没抓到，是真实浏览器跑完一整轮答题到结算才抓到的。

## 二、十个坑（按"坑人程度"排序）

### 坑 1 · 枚举式代码漏一处，就是静默崩溃（v2.9.0）
**症状**：新增「整词听写」题型后，抽到这道题时孩子点什么都没反应。
控制台有一行 `Cannot read properties of null (reading 'addEventListener')`。

**根因**：题型是"枚举"——题干分支、喇叭按钮、选项渲染各写一遍。
新题型只加了出题逻辑，忘了加题干分支；而题干里没有喇叭，
`q.speak` 有值时去找 `#sp-btn` 拿到 null，直接抛错。**崩在渲染里，孩子看不到任何提示。**

**修法**（两层）：
1. 补上分支；
2. **不假设元素一定存在**：`var b = view.querySelector("#sp-btn"); if (b) b.addEventListener(...)`，
   没有喇叭也照样自动朗读，只是少了"再听一遍"的按钮。

**现在由谁守**：`.build/invariant-test.js`
- 「有 speak 就必须有喇叭，没 speak 就不该有」——**严格一一对应**，多一个少一个都红
- 「每种题型都能真的渲染出来」（10 种题型逐一走真实渲染路径）
- 「题型题干标签互不重复」

> 加新题型时必须同时改三处：`games.js` 的 `types`、`views2.js` 的题干分支、
> `invariant-test.js` 的 `TYPES`。漏了最后那处，测试会提醒你。

---

### 坑 2 · 写死的枚举列表会让新增内容"逃过检查"（v2.1.0）
**症状**：v2.0.0 把字库从 400 字扩到 629 字，**新增的 229 字从来没被质检过**。

**根因**：`content-qc.js` 里写的是 `[1,2,3,4,5].map(...)`、`emoji-test.js` 是 `[1..6]`。
加了 `chars-7.js`，这些列表没跟着改。**测试全绿，但只覆盖了 2/3 的字。**

**修法**：`.build/load-chars.js` —— **自动发现 `data/chars-<N>.js`**，以后加批次不用改测试。

**现在由谁守**：`load-chars.js` 自动发现 + `invariant-test.js` 的全库通检
（629 字全部逐条检查组词/例句/拼音）。

> 一般规律：**测试里不要写"有 5 个/有 13 个/有 400 个"这类计数**，
> 要写"笔顺覆盖每一个字""卡片数等于该岛字数"这类**不变量**。
> v2.4.0 把 `smoke.js`/`deploy-verify.js`/`p1-visual-test.js` 里所有写死的数字都改成了不变量断言。

### 坑 3 · 断言写成恒真，等于没有断言（v2.5.0）
**症状**：`self-read-test` 的等待条件写成 `A || !B`，
而 `!B` 在进场第一帧就为真（第 2 个进度点本来就还没点亮）→ 等待立刻返回 →
再断言"第 1 句要标记完成"必然误报。这个错断言**一直存在**，
直到 v2.5.0 改长了 L2 句子、改变了推进耗时才暴露。

**修法**：只等**真正要等的那件事**（第 1 个进度点变成 `done`）。

**同类**：`t("...", () => { ... return r !== false; })` —— 失败分支返回了非空字符串，
于是永远算通过。**失败分支必须返回 `{pass:false}`**，不能返回普通字符串。

> 自查方法：把断言里的条件**手动取反**，看测试会不会红。
> 不会红，就说明它守不住任何东西。

---

### 坑 4 · 随机撞题型 = 每 12 次回归误报 1 次（v2.4.0）
**症状**：`games-pinyin-test` 偶发报「下:该出却没出」，单独跑又通过。

**根因**：`forced()` 靠**反复随机抽题型**（60 次）直到撞到想要的那个。
于是"这个字该出辨调题却没出"和"这次运气不好没撞到"分不清。
实测故障率约 1/12。

**修法**：改用出题器自带的 `preferType` 参数**确定性**要题型。

> 抖动的真正代价不是"测试失败"，而是**让人开始习惯性忽略红灯**。
> 后面还有 6 个版本要跑全量回归，所以当场修掉。

---

### 坑 5 · 坐标系 y 轴方向（v2.7.0）
**症状**：笔画方向判定把"竖"判成"**从下往上**"。孩子照着练会把每一竖都倒着写。

**根因**：`STROKE_DATA.medians` 用的是 **y 轴向上**的坐标（与 hanzi-writer 内部一致），
屏幕是 y 轴向下。比较首尾点时 `dy` 必须取反。

**现在由谁守**：`.build/write-test.js`
- 用「十/木/上/水」这些方向确定的字逐笔验证
- 全库「从上往下」的数量必须是「从下往上」的 **8 倍以上**（实测 729 : 0）

---

### 坑 6 · 分不清的东西不要猜（v2.7.0）
**发现**：只有首尾两点可用时，**"竖"和"撇"在几何上分不开**：

| 字 | 笔画 | ax（横向占比） |
|---|---|---|
| 大 | 第 2 笔（撇） | 0.340 |
| 中 | 第 1 笔（竖） | 0.345 |

差 0.005 —— 任何阈值在这两个之间都是掷硬币。

**修法**：划出"不确定区"，在那里**不给方向**，退回「跟着灰色提示描」，
但**照样把那一笔演一遍**（演示比文字提示更管用）。确定方向覆盖率 79.3%。

> **给错方向比不给方向更糟：孩子会照着错的练。**

### 坑 7 · 内容规则要能机器校验（贯穿全部版本）
写作时最容易犯的错，靠肉眼审几百条是审不出来的：

| 规则 | 谁在守 |
|---|---|
| 短文用字必须在 629 字库内 | `check-passages.js` + `read-test` + `invariant-test` |
| 组词/例句必须含本字 | `content-qc.js` |
| 标点必须全角 | `content-qc.js`（v2.10.0 从警告升级为**致命**） |
| 组词 2~4 字、不重复 | `content-qc.js`（v2.10.0 新增） |
| 拼音必须能被拼音模块认出来 | `content-qc.js`（v2.10.0 从警告升级为**致命**） |
| 配图同岛唯一 | `emoji-test.js` + `content-qc.js` |
| 理解题答案能在证据句里找到、干扰项不在文中 | `read-quiz-test.js` |
| 活动库五条质量守则（可执行/零成本/安全/合规/2~8 分钟） | `quest-test.js` |

**v2.10.0 的 QC 加固一次性抓出 46 处真实缺陷**（例句用了半角逗号/叹号）。
这说明"把建议修的东西升级成必须修"是有回报的。

> 写内容的工作流：
> `node .build/check-passages.js` 边写边查 → 修到全绿 → 再跑回归。

### 坑 8 · 批量文本替换会改坏 JS 语法（v2.10.0，我自己踩的）
**症状**：写了个脚本把 `data/chars-*.js` 里的半角标点换成全角，
结果 `w: [...]` 的冒号变成了 `w：`、数组元素之间的逗号变成了 `，`，**整库语法崩掉**。

**修法**：`git checkout -- data/chars-*.js` 恢复，然后**只对字符串字面量内部**做替换
（正则 `"([^"\\]*(?:\\.[^"\\]*)*)"` 匹配引号内内容，引号外一个字符都不碰）。

> **改数据文件前先确认它在 git 里是干净的**，这样一次 `git checkout` 就能回退。
> 批量替换后必须立刻 `node -e 'require(...)'` 验证语法，别等下一条命令才发现。

### 坑 9 · 服务端已经做了的优化不要再做一遍（v2.10.0）
**先测量再优化**（localhost）：

| 指标 | 实测 |
|---|---|
| FCP | 160 ms |
| DOMContentLoaded | 47 ms |
| 资源 | 45 个 / 传输 2225 KB |
| 最大单文件 | `data/strokes.js` 1.49 MB |
| JS 堆 | 5.3 MB |

**线上实测**：`strokes.js` 已经过 **gzip 压缩 → 628 KB**，且 `Cache-Control: max-age=2592000`（30 天）。

**结论：不动加载链路。** 曾考虑但**明确不做**的两件事：
- ❌ **拆分 `strokes.js` 懒加载**：会引入"首屏笔顺区短暂空白"和"离线首次进入某字无数据"的风险，
  而收益只在首次访问出现（之后都命中缓存）。**为了 200ms 去动核心数据加载，不划算。**
- ❌ **换 brotli**：需要改 nginx 配置（要 sudo 密码），收益约 628 KB → 450 KB。
  记在这里，等下次上服务器时顺手做。

### 坑 10 · 隐私不是文案（v2.6.0）
**跟读录音**引入麦克风权限，三条硬约束**用测试证明，不靠注释**：
1. **绝不外传** —— 用 spy 证明：录音 → 停止 → 回放全程 `fetch` 零调用
2. **随时可拒绝** —— 无权限/无设备/非 https 都给一句人话，且不影响任何其它功能；
   页面上**不会出现一个点了没反应的按钮**
3. **用完就放** —— 换页/关页立刻停掉麦克风轨道并回收 Blob URL
   （否则浏览器标签上的**录音红点会一直亮着**，那是会吓到家长的）

**隐私说明同步更新**（`privacy.html` 新增「🎤 关于麦克风」一节）：
新功能引入新权限，隐私说明必须同步 —— 这是信任问题，不是文案问题。

## 三、加新内容时的检查清单

### 加字（新批次）
1. 生成 `data/chars-N.js`（**自动被发现**，不用改测试）
2. 在 `index.html` 加 `<script src="data/chars-N.js?v=...">`
3. `node .build/gen-strokes.py --apply` 重新生成笔顺
4. `node .build/gen-hanzi-parts.py` 重新生成字理
5. `node .build/content-qc.js` → 必须 0 致命
6. `node .build/emoji-augment.js --apply`（可选：补配图）
7. 跑全量回归

### 加短文
1. 写进 `data/passages2.js`（或新文件，记得 `index.html` 里加载）
2. `node .build/check-passages.js` → 用字/标点/篇幅全绿
3. 在 `data/comprehension.js` 加理解题（**`read-quiz-test` 要求每篇都有题**）
4. 跑全量回归

### 加题型
1. `js/games.js`：写生成逻辑 + 加进 `types` 数组（带可用性判断）
2. `js/views2.js`：加**题干分支**（有 `q.speak` 就必须有 `#sp-btn`）
3. `.build/invariant-test.js`：把题型加进 `TYPES`；如果是听说题，加进 `SPEAK_TYPES`
4. `.build/games-pinyin-test.js`：如果选项有新的 `kind`，加进 `KINDS`
5. 跑全量回归

### 加路由
1. `App.register("名字", {...})`
2. `.build/invariant-test.js` 的 `ROUTES` 里登记（否则这条路由没被守）
3. `sw.js` 由 `stamp-assets.js` 自动生成，不用手改

## 四、当前测试套件（36 个）

```bash
bash .build/run-all.sh              # 全部
bash .build/run-all.sh read quiz    # 只跑名字含 read/quiz 的
```

| 类别 | 套件 |
|---|---|
| 内容质检 | `content-qc` `check-passages`（工具） |
| 字库/题目逻辑 | `games-pinyin-test` `emoji-test` `zili-test` |
| 阅读/理解 | `read-test` `self-read-test` `read-quiz-test` |
| 语音/录音 | `speech-test` `sound-test` `audio-test` `voice-test` `voice-config-test` `phrase-test` `gen-guard-test` |
| 书写 | `write-test` |
| 存档/档案 | `store-test` `cause-test` `profile-test` |
| 线下/活动 | `quest-test` |
| UI 与视觉 | `smoke` `ux-regression` `p0~p3-visual-test` `a4a5-ui-test` `profile-ui-test` `browser-test3` `font-check` |
| 跨模块不变量 | `invariant-test` |
| 离线/统计 | `offline-test` `beacon-test` `report-test` |

**判读顺序**：先看 `invariant-test`（结构一致性）→ 再看 `content-qc`（数据）→
最后看视觉套件。前两类红了通常是真 bug，视觉套件红了先怀疑抖动。
