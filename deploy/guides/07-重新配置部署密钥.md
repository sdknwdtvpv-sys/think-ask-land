# 07 · 重新配置部署密钥（拿不到原密钥时）

> **什么时候用**：要部署网站，但 `hanzi_deploy` 这把私钥拿不到
> （原开发机的外置盘没挂载、或者备份丢了）。**换一台电脑部署**也会用到这份。
>
> **耗时**：约 5 分钟。**做完你会看到**：`ssh ... 'hostname'` 直接打印出服务器主机名，不问密码。
>
> **前置**：你需要能登录 https://console.cloud.tencent.com （这台服务器是你的）。
> 这条路**不需要原来那把密钥** —— 用腾讯云控制台的网页终端登进去就行。

---

## 为什么不能直接"重新生成一把就完事"

服务器只认**它 `authorized_keys` 里登记过的公钥**。所以配密钥是**两边的事**：

| 在哪 | 放什么 | 谁做 |
|---|---|---|
| 本机 `/Users/elliot/Harness/.deploy/` | **私钥** `hanzi_deploy`（+ 公钥 `.pub`） | ✅ **已完成** |
| 服务器 `/home/ubuntu/.ssh/authorized_keys` | **公钥**那一行 | 👉 **你要做这一步** |

> 🔑 **只用 `.pub`（公钥）**。私钥**永远不要**粘贴到任何网页、聊天或控制台里。

---

## 第 1~2 步：本机生成密钥 ✅ **已完成**

已在 `/Users/elliot/Harness/.deploy/` 生成好，权限也设对了：

```
-rw-------  hanzi_deploy        ← 私钥（600，只有你能读）
-rw-r--r--  hanzi_deploy.pub    ← 公钥（要贴到服务器的那一行）
```

指纹（后面和服务器核对用）：

```
SHA256:aHbKoB25skJvDseMMdqycJ0p8bCi68V50UvyoEd+hj8
```

<details>
<summary>如果你想自己重新生成一遍（点开）</summary>

```bash
rm -f /Users/elliot/Harness/.deploy/hanzi_deploy /Users/elliot/Harness/.deploy/hanzi_deploy.pub
mkdir -p /Users/elliot/Harness/.deploy && chmod 700 /Users/elliot/Harness/.deploy
ssh-keygen -t ed25519 -N "" -C "siwendao-deploy" -f /Users/elliot/Harness/.deploy/hanzi_deploy
chmod 600 /Users/elliot/Harness/.deploy/hanzi_deploy
```

⚠️ `-N ""` 的意思是**不设密码**，不是偷懒：部署脚本会**非交互地**调用这把钥匙，
设了密码就每次都要你手输，自动化会直接卡住。
</details>

## 第 3 步：把公钥复制出来

在「终端」里粘贴：

```bash
cat /Users/elliot/Harness/.deploy/hanzi_deploy.pub
```

**做完你会看到**一行**以 `ssh-ed25519` 开头、以 `siwendao-deploy` 结尾**的内容，例如：

```
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAILFZVhVcJ+BT/9ISbeb2ieQ0+Gpls8Gm3sXWAQEU8Hbw siwendao-deploy
```

**整行选中复制**（从头到尾，一个字符都不能少，包括中间的空格）。

## 第 4 步：登录腾讯云控制台，打开服务器终端

1. 浏览器打开 https://console.cloud.tencent.com
2. 进 **云服务器 / 轻量应用服务器**（看你当初买的是哪种）
3. 找到这台机器：**公网 IP `118.25.45.88`**
4. 点 **「登录」** —— 会打开一个**网页版终端**（通常叫「VNC 登录」或「OrcaTerm」）
   - 这就是我们绕过 SSH 密钥的地方：它是从控制台直接连的，**不需要密钥**
   - 如果提示要密码而你不知道：在实例菜单里选 **「重置密码」**，设一个新密码再登
     （重置密码**不会**影响 SSH 密钥，放心做）

> ⚠️ 腾讯云界面的字眼可能和我写的不完全一样（他们改过几次菜单名）。
> 认准 **「登录」/「远程连接」** 这一类按钮，落在**同一个公网 IP** 上就对了。

**做完你会看到**：一个黑色终端窗口，前面有提示符，比如 `ubuntu@VM-xx-xx:~$` 或 `root@VM-xx-xx:~#`。

**先确认你是哪个用户** —— 这决定下一步用哪套命令：

```bash
whoami
```

- 输出 `ubuntu` → 用**情况 A**
- 输出 `root` → 用**情况 B**

## 第 5 步：把公钥写进服务器

### 🔴 两个铁律

1. **只能用 `>>` 追加，绝不能用 `>`** —— `>` 会**清空**文件，把已有密钥全删掉，
   可能连你自己都进不去了。
2. **不要删已有的行** —— 老密钥可能还有别的地方在用。

### 情况 A：当前是 `ubuntu` 用户

把下面**整段**粘进服务器终端（`<公钥>` 换成第 3 步复制的那一行，**连引号一起保留**）：

```bash
mkdir -p ~/.ssh && chmod 700 ~/.ssh
echo '<公钥>' >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
```

### 情况 B：当前是 `root` 用户

⚠️ 注意路径是 **`/home/ubuntu/`**，不是 `~`（`~` 现在是 `/root`）：

```bash
mkdir -p /home/ubuntu/.ssh && chmod 700 /home/ubuntu/.ssh
echo '<公钥>' >> /home/ubuntu/.ssh/authorized_keys
chmod 600 /home/ubuntu/.ssh/authorized_keys
chown -R ubuntu:ubuntu /home/ubuntu/.ssh
```

> **`chown` 这行很关键**：用 root 写出来的文件属主是 root，
> SSH 会因为「authorized_keys 属主不对」**拒绝使用**它，你会看到莫名其妙的
> `Permission denied (publickey)`。

### 写完在服务器上核对（两种情况都做）

```bash
tail -1 /home/ubuntu/.ssh/authorized_keys        # 结尾应是 siwendao-deploy
ssh-keygen -lf /home/ubuntu/.ssh/authorized_keys | tail -1
```

**做完你会看到**指纹是：

```
256 SHA256:aHbKoB25skJvDseMMdqycJ0p8bCi68V50UvyoEd+hj8 siwendao-deploy (ED25519)
```

**指纹和第 2 步一致 = 写对了。** 不一致就说明粘串行了（常见：漏了末尾、或粘成了私钥）。

## 第 6 步：回到 Mac 验证连通

在**本机**新开一个终端窗口：

```bash
ssh -i /Users/elliot/Harness/.deploy/hanzi_deploy \
    -o BatchMode=yes -o StrictHostKeyChecking=accept-new \
    ubuntu@118.25.45.88 'hostname'
```

**做完你会看到**：直接打印出服务器主机名（类似 `VM-4-13-ubuntu`），**不问密码**。

> 第一次连会问 `Are you sure you want to continue connecting?` —— 输 `yes` 回车。
> （加了 `accept-new` 通常就不问了。）

**看到主机名 = 密钥配好了，可以去部署了。**

## 出错了怎么办

| 现象 | 意思 | 怎么办 |
|---|---|---|
| `cp: /Users/elliot/Harness/.deploy/hanzi_deploy: No such file` | 私钥不在该路径 | 回到第 1~2 步 |
| `Permission denied (publickey)` | 服务器没认这把公钥 | ① 第 5 步核对指纹；② 若是 root 写的，补 `chown -R ubuntu:ubuntu /home/ubuntu/.ssh`；③ 确认粘进了 `ubuntu` 的 `authorized_keys` 而不是 root 的 |
| `WARNING: UNPROTECTED PRIVATE KEY FILE` | 私钥权限太松 | `chmod 600 /Users/elliot/Harness/.deploy/hanzi_deploy` |
| `REMOTE HOST IDENTIFICATION HAS CHANGED` | 本机 known_hosts 里有旧记录 | 手动测试加 `-o StrictHostKeyChecking=accept-new`；或 `ssh-keygen -R 118.25.45.88`。**部署脚本不受影响**（它用 `/tmp/hzdeploy/known_hosts`，每次都是干净的） |
| 控制台登不进去 / 不知道密码 | 实例密码丢了 | 控制台里 **重置密码**（不影响 SSH 密钥） |
| `Connection timed out` | 网络或安全组 | 检查腾讯云**安全组**是否放行 22 端口；或先试 `ping 118.25.45.88` |
| 服务器上 `tail` 看不到 `siwendao-deploy` | 粘到别的文件了 | 常见是粘进了 `/root/.ssh/authorized_keys`（root 用户用了 `~`）→ 改用情况 B 的绝对路径 |

## 安全须知

- **私钥 `hanzi_deploy` 绝不能外传** —— 不贴聊天、不贴网页、不进版本库。
  它只在 `/Users/elliot/Harness/.deploy/`（已在仓库**外面**，所以 `git status` 永远不会看到它）。
- **公钥可以随便贴** —— 它本来就是设计成公开的。
- 如果你**同时**还留着原来那把密钥，两把可以并存，服务器会都认。
- 哪天想撤销这把：在服务器上把 `authorized_keys` 里对应那行删掉即可
  （**删单行**，别清空文件）。
